# Лабораторна робота №1: Генерація речення на основі Марковського ланцюга (C++ vs Rust)

## 1. Короткий опис алгоритму
У роботі реалізовано алгоритм побудови Марковського ланцюга 1-го порядку для аналізу вхідного тексту обсягом ~1000 слів. 

**Етапи роботи:**
1. Зчитування та токенізація тексту на окремі слова.
2. Побудова хеш-таблиці переходів (`std::unordered_map` у C++ та `HashMap` у Rust), де ключем є поточне слово, а значенням — вектор усіх можливих наступних слів.
3. Генерація нового речення шляхом випадкового вибору наступного слова до досягнення розділового знака кінця речення (`.`, `!`, `?`) або ліміту слів.

## 3. Аналіз різниці реалізації та результатів

1. **Робота зі рядками та пам'яттю**:
   - **C++**: Використовує `std::string`, що призводить до виділення пам'яті в купі та глибокого копіювання рядків під час запису токенів у хеш-таблицю `std::unordered_map`.
   - **Rust**: Використовує модель запозичення та зрізи рядків `&str`. Хеш-таблиця `HashMap<&str, Vec<&str>>` зберігає лише вказівники на вихідний текст у пам'яті, що оптимізує роботу з пам'яттю.

2. **Безпека та обробка помилок**:
   - У Rust робота з відсутніми ключами та вибором елементів зі списків реалізована через безпечні типи `Option` та сортні методи (`choose()`), що унеможливлює помилки виходу за межі масиву на етапі компіляції.
   - У C++ потрібно явно перевіряти наявність ключів у `std::unordered_map` через `.find()` та контролювати розміри векторів.

---

## 4. Висновки
Обі мови показали високу швидкість виконання (менше 1 мілісекунди) для обробки тексту в 1000 слів. Rust демонструє кращу безпеку роботи з пам'яттю на рівні компілятора та зручний синтаксис запозичення для тексту (`&str`), тоді як C++ надає класичний низькорівневий контроль над контролем пам'яті.
